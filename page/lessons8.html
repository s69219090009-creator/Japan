การออกแบบและสร้างฟอร์ม (Forms)

§ 01  ·  8.1

องค์ประกอบของฟอร์ม

เว็บไซต์ทั่วไปเป็นการสื่อสารทางเดียว (One-way Communication) ที่ให้ผู้ใช้อ่านข้อมูลเพียงอย่างเดียว แต่เว็บไซต์เชิงธุรกิจจำเป็นต้อง "รับฟัง" ข้อมูลจากผู้ใช้ด้วย เช่น การกรอกชื่อผู้ใช้ การส่งข้อความติดต่อ หรือการกรอกที่อยู่จัดส่งสินค้า เครื่องมือที่ทำหน้าที่นี้คือ ฟอร์ม (Forms) ซึ่งเป็นพื้นที่รับข้อมูลที่ผู้ใช้พิมพ์เข้ามา ก่อนรวบรวมเป็นแพ็กเกจส่งไปให้ระบบหลังบ้าน (Server) ประมวลผลต่อไป

8.1.1 โครงสร้าง <form> และการกำหนด Action, Method

ทุกพื้นที่รับข้อมูลต้องถูกประกาศด้วยแท็กคู่ <form>...</form> เปรียบเสมือน "ซองจดหมาย" — ช่องกรอกข้อมูลใดที่หลุดออกไปอยู่นอกแท็กนี้จะไม่ถูกส่งไปยังเซิร์ฟเวอร์เมื่อกดปุ่มส่ง

action ทำหน้าที่เหมือน "ที่อยู่ปลายทางบนหน้าซอง" ระบุ URL หรือไฟล์ฝั่งเซิร์ฟเวอร์ที่จะรับข้อมูลไปประมวลผล ส่วน method ระบุ "วิธีจัดส่งข้อมูล" มี 2 แบบหลัก:

  • GET — เปรียบเหมือนการเขียนข้อความลงบนไปรษณียบัตร ข้อมูลถูกแปะต่อท้าย URL อย่างเปิดเผย เหมาะกับข้อมูลที่ไม่เป็นความลับ เช่น คำค้นหา
  • POST — เปรียบเหมือนการใส่เอกสารในซองทึบแล้วลงทะเบียน ข้อมูลถูกซ่อนไว้เบื้องหลังและส่งได้ปริมาณมาก เหมาะกับข้อมูลส่วนตัวหรือรหัสผ่าน

8.1.1.2 การใช้ <label> คู่กับ <input>

แท็ก <input> คือช่องว่างรอการกรอกข้อมูล แต่ต้องมีแท็ก <label> กำกับเสมอเพื่อบอกผู้ใช้ว่าช่องนี้คืออะไร เทคนิคระดับมืออาชีพคือเชื่อมโยงทั้งสองแท็กด้วยแอตทริบิวต์ id ใน <input> และ for ใน <label> ให้มีค่าตรงกัน ผลคือเมื่อคลิกที่ข้อความ เคอร์เซอร์จะกระโดดเข้าไปในช่องกรอกทันที ช่วยเรื่อง UX และเป็นมิตรกับโปรแกรมช่วยอ่านของผู้พิการทางสายตา

form-basic.html
<!-- สร้างซองจดหมาย ระบุปลายทาง (action) และวิธีส่งแบบปิด (method="POST") -->
<form action="process.php" method="POST">

  <!-- เชื่อม label เข้ากับ input ด้วย for / id ที่ตรงกัน -->
  <label for="username">ชื่อผู้ใช้ (Username):</label>
  <input type="text" id="username" name="user_name">

  <button type="submit">สมัครสมาชิก</button>
</form>

§ 02  ·  8.2

ประเภทของ Input

แอตทริบิวต์ type ในแท็ก <input> เปรียบเสมือน "กิ้งก่าเปลี่ยนสี" — พิมพ์แท็กเดิมแต่เปลี่ยนค่า type หน้าตาและพฤติกรรมของช่องกรอกข้อมูลก็เปลี่ยนไปโดยอัตโนมัติ แบ่งเป็น 2 กลุ่มหลัก คือ กลุ่มข้อความ และกลุ่มตัวเลือก

ประเภทลักษณะการทำงานเหมาะกับ
textช่องกรอกข้อความบรรทัดเดียวมาตรฐานชื่อ-นามสกุล, ชื่อเล่น
passwordพรางตัวอักษรเป็นจุดหรือดอกจัน (*) ทันทีที่พิมพ์รหัสผ่าน ข้อมูลลับ
emailตรวจสอบรูปแบบ @ และโดเมนอัตโนมัติ พร้อมเรียกแป้นพิมพ์ @ บนมือถืออีเมลติดต่อ
radioปุ่มวงกลม บังคับเลือกได้เพียงข้อเดียวในกลุ่มเดียวกันเพศ, ขนาดเสื้อ (S/M/L)
checkboxกล่องสี่เหลี่ยม เลือกได้หลายข้อหรือไม่เลือกเลยก็ได้งานอดิเรกที่ชอบ
select / optionเมนูดรอปดาวน์ ซ่อนตัวเลือกจำนวนมากไว้ กางออกเมื่อคลิกจังหวัด (77 ตัวเลือก)

เลือกเครื่องมือผิดประเภทอาจทำให้ข้อมูลขัดแย้งกันได้ เช่น ใช้ checkbox กับคำถาม "เพศ" ผู้ใช้อาจติ๊กเลือกได้ทั้งชายและหญิงพร้อมกัน ควรใช้ radio แทนเมื่อคำตอบต้องเด็ดขาดเพียงข้อเดียว

input-types.html
<!-- ปุ่มวงกลม (Radio) ต้องตั้ง name ให้เหมือนกันในกลุ่มเดียวกัน -->
<input type="radio" id="male" name="gender" value="male">
<label for="male">ชาย</label>

<!-- กล่องสี่เหลี่ยม (Checkbox) เลือกได้หลายข้อ -->
<input type="checkbox" id="hobby1" name="hobbies" value="reading">
<label for="hobby1">อ่านหนังสือ</label>

<!-- เมนู Dropdown -->
<select name="province">
  <option value="bkk">กรุงเทพมหานคร</option>
  <option value="cnx">เชียงใหม่</option>
</select>

ในยุค Mobile First Design ที่ผู้ใช้เข้าเว็บผ่านสมาร์ตโฟนเป็นหลัก การใช้ <select> กับตัวเลือกตั้งแต่ 5 รายการขึ้นไปช่วยประหยัดพื้นที่หน้าจอ และเบราว์เซอร์บนมือถือยังมีระบบวงล้อตัวเลือก (Native Picker) ช่วยให้ปัดเลือกได้สะดวกรวดเร็วอีกด้วย

§ 03  ·  8.3

การตรวจสอบข้อมูล (Validation)

เปรียบเสมือน "พนักงานตรวจเอกสาร" ที่คอยดักจับความถูกต้องของข้อมูลทุกช่องทันทีที่ผู้ใช้กดปุ่มส่ง (Submit) หากพบข้อมูลไม่ครบหรือผิดเงื่อนไข ระบบจะระงับการส่งและแจ้งเตือนให้แก้ไขก่อนเสมอ ในอดีตต้องเขียน JavaScript ที่ซับซ้อน แต่ปัจจุบัน HTML5 มีระบบตรวจสอบอัตโนมัติในตัว (Built-in Form Validation) เพียงเติมแอตทริบิวต์สั้น ๆ ลงในแท็ก <input>

8.3.1 การคุมข้อมูลเบื้องต้นด้วย Attribute

  • required — เปรียบเหมือนเครื่องหมายดอกจันสีแดง (*) บังคับให้กรอกข้อมูลในช่องนั้นก่อนส่งฟอร์มได้เสมอ
  • min / max — กำหนดขอบเขตต่ำสุด-สูงสุด มักใช้กับ type="number" หรือ type="date" เช่น จำกัดอายุผู้สมัครงานไว้ระหว่าง 18–60 ปี
validation.html
<label>ชื่อ-นามสกุล (บังคับ):</label>
<input type="text" name="fullname" required>

<label>อายุ (ต้องมีอายุ 18-60 ปีเท่านั้น):</label>
<input type="number" name="user_age"
       min="18" max="60" required>

สรุปท้ายบท

ภาพรวมของบทนี้

บทนี้เชื่อมโยงหลักการสื่อสารแบบสองทาง (Two-way Communication) เข้ากับการสร้างแบบฟอร์มจริงบนเว็บไซต์ โดยแท็ก <form> ทำหน้าที่เป็นพื้นที่รับข้อมูลผ่านแอตทริบิวต์หลักอย่าง action และ method เพื่อระบุปลายทางและวิธีส่งข้อมูล (GET แบบเปิดเผย หรือ POST แบบซ่อนไว้เบื้องหลัง)

การเลือกประเภทของ <input> ให้เหมาะสมกับลักษณะข้อมูล พร้อมจับคู่กับ <label> เสมอ ช่วยลดความผิดพลาดจากผู้ใช้งานและเพิ่มประสบการณ์การใช้งานที่ดี ในขณะที่การใช้ Validation อัตโนมัติของ HTML5 ผ่านแอตทริบิวต์ required, min และ max ช่วยดักจับข้อมูลที่ไม่ถูกต้องก่อนส่งออกจากเบราว์เซอร์ นับเป็นพื้นฐานสำคัญก่อนต่อยอดด้วยภาษา JavaScript เพื่อสร้างการตรวจสอบที่ซับซ้อนและการโต้ตอบ (Interactive) ในบทถัดไป
